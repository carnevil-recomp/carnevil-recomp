# carnevil-decomp

Matching decompilation of Midway's CarnEvil (1998, Seattle hardware: MIPS R5000, 3dfx
Voodoo, DCS2 sound) and a native PC port built from the same source. The goal is a 1:1
port: every byte of the original `GAME.EXE` v1.0.3 is rebuilt and compared on each build,
and the port runs that code on a thin hardware layer. See `docs/PLAN.md` for the plan and
`docs/` for the notes of each phase.

## Where it stands
- **Byte-exact rebuild**: `make` reproduces GAME.EXE from `asm/` + `src/` and fails on any
  difference. The GOOSE operating-system library and the DCS sound library (27 modules) and
  the first game modules are matched C; the rest is still assembly.
- **The port** (`make port`) boots the game's real main process: hardware info screen,
  CMOS, audits and adjustments, high scores, pricing and credits, the sound board bring-up,
  then the attract mode with its movies, text, music and sound effects. Coins, start
  buttons, service credit and the volume buttons work. A start runs the real game flow:
  the level-select gallery, Rickety Town with its movie, script, lights, sound and music,
  Krinkle and the termites, the light gun (the mouse), muzzle flashes and hit effects.
  What the game code still lacks is stubbed, and every stub announces itself (below).
- macOS (Apple Silicon and Intel), Linux (x86_64) and Windows (32-bit, cross-compiled from Linux) build today.

## Layout
- `docs/` plan and notes; `config/` symbols and module ranges; `include/` shared headers;
  `test/` oracle data; `experiments/` throwaway investigations.
- `asm/` the disassembly (generated by `make`, git-ignored).
- `src/` the C source. `goose/` and `sound/` are the SDK's library sources, generated by
  `make` from your SDK checkout plus `patches/`, so nothing of Midway's is committed. `game/`
  is the game, by subsystem:
  - `core/` boot, attract, game flow, waves, players, the gun, credits, audits, the select screen
  - `render/` camera and vector maths, the model renderer, clipper, quads, text, sprites,
    textures and lights
  - `movie/` the movie player, its scripts and the screen shake
  - `sound/` the level sound helpers and the sound board I/O
  - `enemies/` the spawn tables, the shared enemy code, each enemy, the weapons and effects
  
  Generated tables (`*_data.c`, `movie_scripts.c`) sit next to the code that uses them.
- `port/` the host layer: `runtime/` HAL, scheduler, memory, disk; `video/` the OpenGL
  renderer and window; `audio/` audio output and the virtual DCS sound board; `stubs/` the
  stand-ins for game code not decompiled yet; `tests/` the self-test; `third_party/` the
  vendored DCS decoder.
- `tools/`: `build/` the compiler wrapper, assembler fix-ups, disassembler, EXE packer and
  `check.sh`; `match/` the function matching tools; `extract/` the table extractors that write
  the `*_data.c` files; `rom/` the disk image and file system readers (and the original
  hand extractors in `rom/legacy/`); `analysis/` disassembly viewers and the Binary Ninja client.
- `original/` (git-ignored) holds your game data and SDK checkout via `setup.sh`.

## Getting started
The repository contains no game data and no SDK. Three things come from elsewhere, and
`setup.sh` only links to them (the links live in the git-ignored `original/`):

1. **Your own dump of the CarnEvil v1.0.3 hard disk** (MAME set `carnevil`), as a raw
   image (`chdman extractraw`). The port needs both the game's files and the raw image (the
   movies are raw partitions outside the filesystem); `setup.sh` extracts the files for you.
2. **The Midway Seattle SDK**: `git clone https://github.com/historicalsource/midwayvideo`
   (18 MB). The port only needs its headers; the byte-exact rebuild also runs its original
   DOS compiler.
3. **This repository.**

### Play the port
Needs python3, clang and make. On Linux (x86_64) also SDL2 and OpenGL headers, e.g. on
Ubuntu `sudo apt install clang make python3 pkg-config libsdl2-dev libgl-dev`.
```
git clone https://github.com/historicalsource/midwayvideo ../midwayvideo
./setup.sh --raw /path/to/carnevil.raw --sdk ../midwayvideo
make port
build/host/carnevil --partition original/partition --raw original/carn.raw     # macOS
build/linux/carnevil --partition original/partition --raw original/carn.raw    # Linux
```
Windows: cross-compile from Linux with MinGW-w64 (`sudo apt install mingw-w64`) and SDL2's
MinGW development package (SDL2-devel-2.30.9-mingw from libsdl.org, unpacked under
`~/win-deps`, or pass `SDL2_MINGW=.../i686-w64-mingw32`):
```
make port WINDOWS=1          # build/win/carnevil.exe and SDL2.dll
carnevil.exe --raw C:\path\to\carnevil.raw
```
It is a 32-bit program (the game's own 32-bit layout) and runs on 64-bit Windows; Wine runs it
too. macOS and Linux keep separate outputs (`build/host` + `build/port` on macOS, `build/linux` on
Linux; the MIPS binutils in `tools/mipsel-elf-binutils` and `tools/mipsel-elf-binutils-linux`),
so one checkout shared with a VM builds on both without one clobbering the other.
Without `setup.sh` the port only needs the disk image: `build/host/carnevil --raw
/path/to/carnevil.raw` unpacks the game's files from the image's file system into
`state/partition` on the first run (no Python needed) and plays from there.
`./setup.sh --partition DIR` works instead of `--raw` if you extracted the files yourself
(`tools/rom/legacy/` has the stand-alone extractors); add `--raw` as well for the movies.

### Verify the byte-exact rebuild (for working on the decompilation)
Additionally needs python3's capstone (`pip install capstone`), DOSBox-X on the PATH (it
runs the SDK's DOS compiler for the C modules) and the MIPS binutils, built once:
```
tools/build/get-binutils.sh      # mipsel-elf as/ld into tools/ (git-ignored)
make                       # rebuild GAME.EXE from asm/ + src/ and check it is byte-identical
make host                  # native compile of every C module + self-test
```
`make` and `make port` stop with a message naming the missing piece if a link is absent.

## Running the port
```
build/host/carnevil --partition original/partition --raw original/carn.raw
```
Options: `--state DIR` where the port keeps the game's CMOS image and the files the game
writes (default `state/`; delete it for a factory-fresh boot), `--wav FILE` to capture the
soundtrack, `--frames N` to stop after N frames, `--fast` to disable frame pacing,
`--headless` for no window, `--dump frame.ppm` or `--dump-every PREFIX N` for screenshots,
`--violence 0..3` to set the operator's VIOLENCE adjustment (0 none: smoke instead of blood,
no acid or flamethrower pickups; 1 green blood; 2 red blood; 3 full gore, the factory default) or
`--adjust N=V` for any adjustment by its number in the game's ADJUST.FMT (e.g. 58=0 turns BIG
BABY off); both are written into the CMOS state as the test menu would and persist, `--fullscreen` to start fullscreen (the desktop's resolution, no display mode change; the
picture keeps its shape with black bars), `--borderless` for a window without a title bar (the
window is resizable either way), `--crosshair 0` for no port crosshairs, `--hires` to draw at the window's resolution in 24-bit colour instead of the cabinet's 400x256
16-bit picture (the default, see docs/port.md), `--load-time X` to scale level-load time (default 2.8, a test calibration explained in
docs/port.md; 1 is the port's instant loading), `--press FRAME:SWITCH,...` to script cabinet switches for tests, `-v` (twice for every
ioctl) for traces. `CARNEVIL_PARTITION`, `CARNEVIL_RAW` and `CARNEVIL_STATE` are the
environment equivalents.

## Controls
The cabinet's switches are mapped to the keyboard, and the mouse is player 1's light gun:
move it over the picture to aim (the game's own gun code converts the position through its
calibration) and click to shoot. Pointing off the picture counts as pointing off the screen,
which is how the original reloads.

| Key | Cabinet switch |
|---|---|
| `5` or `C` | Coin (left slot) |
| `1` | Player 1 start |
| `2` | Player 2 start |
| `9` | Service credit |
| `-` / `=` | Volume down / up (hold: the volume bar appears) |
| `Space` | Player 1 pump |
| Left mouse button or `Left Ctrl` | Player 1 trigger |
| Mouse position | Player 1 aim |
| `F2` | Test switch (diagnostics not implemented yet) |
| `F11` or `Alt+Enter` (macOS: `Option+Return`, `Ctrl+Cmd+F` or the green button) | Fullscreen on/off |

Gamepads (SDL game controllers on Linux and Windows, Apple's GameController framework on
macOS): the first connected pad plays player 1 and the second player 2. Moving the mouse
gives player 1 back to the mouse.

| Pad | Cabinet |
|---|---|
| Left stick or d-pad | Aim (the stick moves the crosshair; the further, the faster) |
| A or right trigger | Trigger |
| B or left trigger | Pump |
| Y or right shoulder | Reload (points the gun off the screen and fires, as on the cabinet) |
| Start / Menu | That player's start |
| Back / Options | Coin (player 1 the left slot, player 2 the right) |

The cabinet's light guns need no on-screen sight, so the original draws none during play
(only on the initials board). Like MAME, the port draws one over the picture for each aiming
player (player 1 red, player 2 blue) and hides the system pointer over the picture;
`--crosshair 0` turns that off.

For scripted runs, `--press` takes these switch names: `coin`, `coin2`, `coin3`, `coin4`,
`bill`, `start1`, `start2`, `service`, `test`, `slam`, `voldown`, `volup`, `p1a`..`p1d`,
`p2a`, `p2b`, `trigger`, `pump`, `trigger2`, `pump2` (each press is held for 6 frames);
headless shots go to the screen centre, or to `CARNEVIL_AIM=x,y` (x 0..400, y 0..256 from
the bottom). `CARNEVIL_PADSIM="FRAME:PAD:LX,LY,BUTTONS;..."` stands in for a gamepad
(the stick and `PAD_*` button bits from `port/runtime/hal.h`, from that frame on). Coins are not counted while the boot load runs (until about frame 960 with
the default `--load-time`), so scripts press later:

```
build/host/carnevil --partition original/partition --raw original/carn.raw \
    --headless --fast --frames 1150 --press 1000:coin,1010:coin,1050:start1
```
This table grows as inputs are added (the test menu).

## Faithfulness
Game and library code is transcribed from the disassembly and checked byte-exact where it
has been matched; modules not yet matched are marked in `docs/port.md`. The same C source
goes into the byte-identical GAME.EXE (`make`, where the untranscribed functions are still
the original assembly) and into the port (`make port`, which links only C). The hardware is
the only thing replaced: `port/` stands in for the disk, I/O ASIC, CMOS, security PIC,
Voodoo and the DCS2 board, following the SDK sources and MAME as the reference. Files the
game writes go to the state directory so an extracted partition is never modified.

Game code the port does not have in C yet is a stub, never a silent one: each stub prints
`[stub] name reached at vblank N` the first time it runs and the run ends with the list of
every stub it touched. That list is the work queue; a stub is retired by transcribing its
function and matching it with `tools/match/trymatch.sh`. Host-only code paths in game sources
are `#ifdef PORT_HOST` blocks, so the matching build never sees them.
